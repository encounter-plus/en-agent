# Правила версионирования для агента

## Версия исходников и версия комплекта

- `package.json.version` — версия исходного launcher. Обновляй также соответствующую запись в `package-lock.json`.
- `release.json.id` — идентификатор конкретного неизменяемого комплекта: launcher, инструкции, Node, OpenCode, skills, MCP и браузерные инструменты. Это версия установленного продукта; её нельзя определять только по `package.json` launcher.
- `skillsVersion` и `mcpVersion` берутся из манифестов фактически включённого en-skills и его runtime. Их номера независимы от launcher. Для изменений этих компонентов применяй правила их собственного `VERSIONING.md`.
- `sequence` задаёт порядок обновлений независимо от номера версии. При подготовке следующего обновления используй число больше максимального уже выпущенного в целевом канале; для локальной установки учитывай также её `highestSequence` и подготовленные выпуски. Значение по умолчанию в seed-скрипте не является источником следующего номера.

## Когда повышать номер

| Изменение | Версия launcher |
| --- | --- |
| Совместимое исправление запуска, таймаута, изоляции или языка инструкции | PATCH |
| Новая совместимая возможность launcher | MINOR |
| Несовместимый интерфейс или конфигурация | MAJOR для 1.x и выше; MINOR для 0.x с описанием перехода |
| Только тесты или документация разработчика | Без повышения |

Изменение поставляемых инструкций считается изменением поведения. Применяй максимальное необходимое повышение один раз на выпуск, обнуляя младшие разряды. Перед распространением изменённого launcher повышай версию исходников, если она ещё не повышена для этого неопубликованного набора изменений.

Любое изменение файлов комплекта, в том числе только вложенного en-skills или браузерного MCP, требует нового `id`, пересчитанных хешей и нового `sequence` при поставке обновления. Для stable используй `X.Y.Z`, для предварительной проверки — `X.Y.Z-preview.N`, для локальных испытаний — `X.Y.Z-local.YYYYMMDD.N`. Выбирай базовый номер комплекта по влиянию всех его изменений: исправление — PATCH, новая возможность — MINOR, несовместимость — MAJOR (MINOR до 1.0). Номер исходного launcher может отличаться от номера комплекта.

Уже поставленный ID не переиспользуй для других байтов; следующий локальный прогон с изменениями получает новый суффикс. Stable-тег совпадает с ID без префикса `v`. Предварительные и локальные сборки не становятся stable автоматически.

## Подготовка и проверка

1. Прочитай исходные версии, текущий/подготовленный манифест установки и состояние канала, если готовится публикация. Зафиксируй исходные номера и совместимость. Существующие расхождения между историческим ID комплекта и версией launcher не исправляй переименованием установленного выпуска.
2. До упаковки обнови затронутые исходные версии и lock-файлы; передай сборщику новый ID и sequence явно. Для обычной разработки без поставки достаточно указать необходимое повышение в результате работы.
3. Пересобери комплект; проверь манифест, версии вложенных компонентов и хеш каждого файла через существующую проверку bundle. Редактируй исходники, затем собирай новый выпуск, сохраняя прежний для отката.
4. Выполни тесты launcher и проверки затронутых компонентов. Для изменения инструкций/импорта проверь установленный комплект на синтетической игре с реальной моделью; для изменения браузера — фактический запуск превью. Проверь сохранность конфигурации, авторизации, памяти игры и пользовательских данных при обновлении. Реальную игру для мутаций не используй.
5. Подписание, установка и публикация выполняются в рамках явного запроса пользователя. Для stable проверь полный набор assets и чистую установку до назначения latest, как описано в README.
6. Сообщи версии launcher, skills, runtime, ID/sequence комплекта, выполненные проверки и фактическую стадию: подготовлен, установлен или опубликован.

`schemaVersion`, `bootstrapProtocol`, `storageEpoch` и `opencode.configVersion` — версии форматов и протоколов, а не счётчики выпусков. Меняй их только вместе с реализацией и проверкой совместимости/миграции. Повышение версии продукта само по себе не делает новый формат поддерживаемым. При откате сохраняй защиту от повторной установки старого sequence; не обнуляй пользовательское состояние ради обновления.
