# Техническое руководство en-agent

[Пользовательская инструкция](../README.md) · [Сборка выпуска](releases.md)

## Реализовано

- Windows launcher с выбором папки/названия игры и кнопкой завершения работы. Запуск через нативный `en-agent.exe` установленного комплекта, без терминала; OpenCode открывает готовый GUI в браузере.
- Создание игры по шаблону установленного en-skills. Канонические инструкции и память — в en-skills, launcher вызывает его initializer. Повторная инициализация сохраняет файлы.
- Общая версионированная установка вне игр; изолированные данные OpenCode, Encounter и управляемого браузера.
- Три MCP: Encounter runtime, авторские инструменты, официальный Playwright MCP с выбранным видимым браузером и отдельным профилем без расширения.
- Wikipedia search/read с сохранением infobox; публичные Google Docs/Sheets через существующий reader en-skills; встроенный поиск OpenCode через Exa.
- `preview_html` раздаёт только `artifacts/`, возвращает URL для управляемого браузера; сохранение HTML/CSS/JS вызывает reload страницы. Это черновик, проверка движка Encounter выполняется отдельно.
- Автообновление проверенного комплекта: Ed25519-подпись манифеста, SHA-256 каждого файла, подготовка в фоне, применение на следующем запуске, проверка OpenCode/MCP, возврат версии и данных при неудачном старте. Автообновление самого OpenCode выключено через `update: "disable"`.

## Границы первой реализации

Поддерживается только OpenCode v2; закреплён и проверен 2.0.32 (`@opencode/cli`, не старый `opencode-ai`). Комплекты v1 отклоняются. Launcher запускает изолированный `serve --stdio`, проверяет API и MCP, затем открывает готовый GUI по одноразовой pairing-ссылке. Пароль сервера создаётся на запуск, не сохраняется и не выводится в журнал. Общий фоновый сервис OpenCode не используется. Windows + установленный поддерживаемый браузер — текущая целевая среда. Нативный EXE запускает PowerShell GUI; политика организации должна разрешать PowerShell. Подписание EXE не отменяет политики организации.

Windows ZIP, установщик и подписанные файлы обновления публикуются в GitHub Releases. Подпись манифеста обновлений не является Authenticode-подписью установщика. Локальный seed — средство разработчика. Google Docs/Sheets редактируются через браузер: агент читает источник, показывает конкретные правки, получает одобрение и проверяет сохранение. Для закрытых документов пользователь входит в Google в управляемом браузере. Ключ Exa можно передать через `EXA_API_KEY`; инструкция ниже. Подключение модели выполняется в готовом GUI OpenCode.

Аккаунт Encounter подключается кнопкой «Аккаунт Encounter» в launcher. Авторские live-записи и платные модельные вызовы не входят в автоматические тесты.

## Аккаунт Encounter

Нажмите «Аккаунт Encounter» в окне launcher. В отдельном нативном окне Windows укажите только логин и пароль, затем «Сохранить аккаунт». Игра и её домен для сохранения не нужны. Без домена аккаунт сохраняется без проверки входа. После создания папки агент выяснит домен в чате, когда потребуется подключение к движку, и вызовет `encounter_connect_domain`; состояние проверяется через `encounter_account_status`. При работе только над замыслом подключение не требуется. Пароль никогда не передаётся в чат. Сейчас поддерживается один аккаунт и один активный домен.

Для современного движка вход выполняется через Encounter API. Для старого открывается отдельное видимое окно выбранного браузера: приложение заполняет однозначно распознанную форму и один раз нажимает Sign in / Войти. Если сайт требует CAPTCHA, кнопка недоступна или вход не завершился, пользователь продолжает в открытом браузере. Автоматических повторных отправок нет. Если форму нельзя надёжно распознать, заполните её в этом окне вручную. После появления признаков входа под указанным логином приложение сохраняет cookies и закрывает окно. Закрытие окна до входа отменяет попытку. Доступность редактирования конкретной игры отдельно проверяет MCP.

Пароль и сессия хранятся в Windows Credential Manager; в папку игры, историю чата, манифест выпуска и обычные JSON-настройки они не записываются. В настройках остаются домен, имя пользователя и идентификатор профиля. Секреты доступны программам этого пользователя Windows: это не изоляция от произвольных локальных программ. Для другого компьютера или пользователя Windows потребуется новый вход. «Забыть аккаунт» удаляет сохранённые данные этого подключения; это не выход из всех сессий на сайте Encounter.

При явной ошибке авторизации MCP сообщает менеджеру аккаунта. Для современного движка допускается одна попытка восстановить вход с сохранённым паролем; если она не помогла, открывается окно аккаунта. Для старого движка восстановление выполняется через кнопку входа и видимый браузер. Сетевые ошибки, HTTP 403 и неизвестный результат записи не вызывают автоматический повтор входа. Неоднозначная проверка авторизации/CAPTCHA старого движка требует проверки в браузере, а не утверждения, что пароль неверен. Повторяющиеся ошибки не открывают множество окон.

После входа вернитесь в чат и попросите продолжить с перечитывания игры. Неудачная операция автоматически не повторяется: агент должен проверить актуальное состояние и заново подготовить зависимые изменения. Обновление комплекта сохраняет аккаунт; восстановление резервной копии данных приложения не откатывает секреты системного хранилища.

Один launcher обслуживает один активный процесс OpenCode. Закрытие вкладки браузера оставляет процесс работающим; кнопка «Завершить работу» в launcher останавливает принадлежащее ему дерево процессов. После аварийного завершения stale `launcher.lock` требует проверки владельца и ручного удаления; durable recovery не реализуется.

## Поиск: Exa и Википедия

Общий поиск выполняет встроенный `websearch` OpenCode v2. Launcher выбирает `websearch: {provider: "exa"}`; отдельного поискового MCP и Brave в комплекте больше нет. Попросите: «Найди источники об истории обсерватории и дай ссылки». Для чтения известного URL доступны встроенный `webfetch` и управляемый браузер. Поисковые запросы отправляются Exa: используйте публичные формулировки без секретных кодов игры.

### Как добавить ключ Exa

1. Создайте аккаунт на [dashboard.exa.ai](https://dashboard.exa.ai/) и выпустите API key. Это ключ поиска, отдельный от ключа модели/OpenRouter.
2. В Windows откройте «Изменение переменных среды текущего пользователя» и создайте пользовательскую переменную `EXA_API_KEY` со значением ключа. Администраторские права не нужны. Храните ключ вне папки игры и сообщений чата.
3. Завершите en-agent. Выйдите из учётной записи Windows и войдите снова, чтобы запуск через ярлык получил новую переменную, затем откройте `en-agent.exe`.
4. Попросите выполнить поиск через `websearch`. Использование и баланс проверяйте в кабинете Exa. При ошибке авторизации проверьте ключ, при исчерпании кредита — баланс; повторные запросы не исправляют лимит.

Launcher передаёт окружение процессу OpenCode; ключ не включается в манифест или конфигурацию комплекта. Переменные среды доступны программам текущего пользователя и не являются зашифрованным хранилищем. Кнопка «Поиск Exa» позволяет сохранить, проверить, заменить или удалить ключ в Windows Credential Manager отдельно для установки. Он передаётся в окружение OpenCode при запуске и имеет приоритет над пользовательской переменной EXA_API_KEY. Изменения применяются при перезапуске; инструкция находится в README. Официальная инструкция OpenCode также предусматривает подключение Exa через `/connect` в TUI; это альтернативный способ, не обязательный шаг для нашего GUI-запуска.

### Бесплатный тариф и работа без ключа

По [тарифам Exa](https://exa.ai/docs/admin/pricing), проверенным 21 октября 2026 года:

- Личный аккаунт получает **$10 кредитов**, а первого числа каждого месяца бесплатный баланс восстанавливается до **$10**. Это не накопление по $10 поверх остатка.
- За завершение onboarding первая команда получает **разовый бонус $10**. Платёжный метод для бесплатного тарифа не требуется.
- $10 хватает примерно на **2500 Lite-запросов** ($4/1000) или **1428 Auto-запросов** ($7/1000) при базовом числе результатов и без дополнительных платных операций. Это ориентиры API, а не обещанное число вызовов в OpenCode: встроенный адаптер использует `web_search_exa` через MCP и сам не задаёт режим Lite.

**Без ключа поиск не обязательно отключён.** OpenCode 2.0.32 обращается к публичному Exa MCP, который допускает бесплатный доступ с ограничением частоты без авторизации. Численный лимит этого режима Exa в указанной документации не фиксирует; он не равен $10 кредитов вашего аккаунта. При ограничении сервис может вернуть 429; подождите или подключите личный ключ. При выбранном `exa` переключения на другие провайдеры нет. Интернет нужен в обоих режимах; Wikipedia, публичное чтение Google и локальный preview не зависят от ключа Exa.

Источники: [поиск в OpenCode 2.0.32](https://github.com/anomalyco/opencode/blob/v2.0.32/services/www/src/docs/content/websearch.mdx), [адаптер Exa](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/core/src/plugin/websearch/exa.ts), [режимы доступа Exa MCP](https://exa.ai/docs/get-started/exa-mcp). Тарифы и лимиты могут измениться.

### Карточка Википедии

`wikipedia_search` ищет статьи на русском или английском без API key. `wikipedia_read` принимает `language`, `title` и необязательный `mode`:

- `article` (по умолчанию): текст статьи, разделы и отдельно карточки `infoboxes`.
- `infobox`: только карточки, заголовок, URL, номер редакции и время получения; текст статьи и разделы не попадают в контекст.

Например: `{"language":"ru","title":"Эйфелева башня","mode":"infobox"}`. Если карточка не найдена, результат содержит пустой список и `infoboxStatus: "absent_in_returned_html"`. Это данные таблицы, а не снимок её оформления; внешний вид смотрите в управляемом браузере.

## Разработка и локальный пилот

Нужны Node >=24, собранный соседний en-skills, его runtime и бинарник OpenCode 2.0.32. `npm ci`, затем `npm test`; `npm run test:browser` дополнительно открывает видимый браузер агента и проверяет auto-reload на синтетической странице.

```powershell
node src/seed-local.mjs --home .local/exa-ready --skills ../en-skills --opencode C:/absolute/path/opencode.exe --id 0.0.1-local.1 --sequence 1
node src/cli.mjs --home .local/exa-ready --game .local/games/demo --name "Пилот" --no-browser --smoke
node tests/opencode-smoke.mjs .local/exa-ready .local/games/demo
node tests/search-smoke.mjs .local/exa-ready
node tests/question-gui-smoke.mjs .local/exa-ready
```

Seed копирует бинарники, навыки и MCP в независимую папку. Для обычного запуска откройте `.local/exa-ready/en-agent.exe`. Источники и node_modules не нужны автору после сборки. Каталог `.local/` исключён из Git; в нём могут находиться история и авторизация.

Структура установки:

```text
en-agent.exe, Launch.ps1     нативная точка запуска и обновляемый GUI
state.json                  текущая/подготовленная версия
channel.json                HTTPS-адреса канала и доверенный public key
releases/<id>/              OpenCode, Node, launcher, skills, MCP
data/                       настройки, чаты и профили
backups/                    снимок перед переключением
staging/                    незавершённые загрузки
```

## Выпуск и обновление

Выпуск — точные версии и контрольные суммы всех файлов, включая Node, launcher и browser MCP. Одинаковые package version en-skills не заменяют проверку hash файлов. Манифест разрешает только `storageEpoch: 2` и `opencode.configVersion: 2`; неизвестная схема требует отдельной миграции. Новый чатовский контекст загружает новые skills; старые сообщения не переписываются.

Ключ подписи хранится у сопровождающего вне репозитория. `prepare-release.mjs` проверяет комплект и готовит подписанный канал и assets локально; ничего не загружает:

```powershell
node src/prepare-release.mjs --bundle PATH_TO_VERIFIED_BUNDLE --out RELEASE_OUTPUT --id 0.0.1 --sequence 1 --key PRIVATE_KEY_PATH --approved
```

Канал автообновлений — GitHub Releases `encounter-plus/en-agent-updates`; пользовательские EXE, ZIP и контрольные суммы публикуются отдельно в `encounter-plus/en-agent`. Для комплекта `0.0.1` создать release с тегом `0.0.1` (без `v`); загрузить подписанный `channel.json` и содержимое каталога `0.0.1/` как assets с именами SHA-256. Только после проверки полного набора assets выпуск становится latest. Draft/prerelease не используются как stable-канал.

На клиенте `channel.json` содержит `manifestUrl`, `assetsUrl` и доверенный PEM `publicKey`; пример — `config/channel.example.json`. Адрес манифеста: `https://github.com/encounter-plus/en-agent-updates/releases/latest/download/channel.json`; корень assets: `https://github.com/encounter-plus/en-agent-updates/releases/download/`. Public key устанавливается вместе с доверенной первоначальной поставкой, а не скачивается из проверяемого канала. HTTP redirects допускаются только на HTTPS; контрольные суммы проверяются после загрузки. Скачивание выполняется в фоне после готовности GUI и прерывается при остановке launcher.

Перед одобрением проверить `npm test`, видимый browser smoke, настоящий OpenCode с тремя MCP, две игры без Git, авторский workflow на выбранной модели, вход Encounter и браузерный процесс Google и обновление между двумя комплектами. Bootstrap protocol 1: Launch.ps1, Install.ps1 и Uninstall.ps1 заменяются атомарно из проверенного комплекта после успешного запуска. Минимальный EXE-dispatcher обновляется установщиком; неизвестный bootstrapProtocol отклоняется.

Контракты v2 сверены с исходниками тега [v2.0.32](https://github.com/anomalyco/opencode/tree/v2.0.32): [конфигурация](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/schema/src/config.ts), [MCP](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/schema/src/mcp.ts), [API и pairing](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/protocol/src/groups/server.ts). Шаблон папки игры en-skills остаётся версии 1: его версия независима от OpenCode и схемы хранения launcher. Старые локальные v1-пилоты не обновляются на месте; для v2 создаётся новая установка.

## Браузер агента

При запуске через `en-agent.exe` выберите браузер перед выбором папки игры. Настройка сохраняется для всех игр. Автоматический режим ищет Chrome, затем Edge, затем установленные сборки Chromium/Firefox для Playwright. Явный выбор недоступного браузера завершает запуск с сообщением; скрытой замены нет. MCP и вход Encounter получают один выбранный исполняемый файл. Для каждого браузера MCP использует отдельный профиль, вход Encounter — отдельную временную сессию. Личный профиль не используется.

Обычный установленный Firefox не подключается как Firefox Playwright: в списке обозначена именно сборка для автоматизации, если она установлена. GUI OpenCode открывается в системном браузере по умолчанию независимо от выбора браузера агента. `-ResumeLastGame` сохраняет прежний выбор без повторного диалога.

### Подготовка Windows ZIP сопровождающим

После проверки комплекта и создания подписанного канала через `prepare-release.mjs`:

```powershell
node src/package-windows.mjs --bundle PATH_TO_VERIFIED_BUNDLE --envelope RELEASE_OUTPUT/channel.json --public-key RELEASE_OUTPUT/public-key.pem --out WINDOWS_OUTPUT
```

Сборщик копирует только файлы из проверенного манифеста; данные локального пилота, игры, аккаунты и приватный ключ не включаются. ZIP содержит Node, OpenCode, skills, MCP, launcher, публичный ключ и настройку канала. Загрузите ZIP и `.sha256` в пользовательский Release `en-agent`. Подписанный `channel.json` и assets обновления публикуются только в `en-agent-updates`. Сначала проверьте чистую распаковку и запуск, затем публикуйте выпуск. Приватный ключ храните отдельно и используйте тот же ключ для следующих обновлений.


## Диагностика и настройки

Launcher показывает этап запуска и отдельные состояния Encounter, author_tools и browser MCP. «Настройки» показывают текущую/подготовленную версию, выбранный браузер и доступные браузеры. Смена браузера требует подтверждения остановки текущей работы и перезапускает OpenCode, MCP и вход Encounter вместе. Повторный запуск поднимает существующий launcher через ограниченное текущим Windows-пользователем именованное событие; mutex защищает диалоги и запуск.

«Журнал» открывает структурные события. «Экспорт диагностики» создаёт `diagnostic-export.json` в папке установки, в том числе после ошибки запуска. Экспорт содержит только разрешённые поля: этап, категорию, версию, браузер и состояния MCP/обновления. В нём нет текста чатов, паролей, cookies, токенов и pairing-ссылок. Журналы `diagnostics/events-*.jsonl` хранятся до 7 дней, каждый ограничен примерно 256 KiB; очистка выполняется при следующем событии. Launcher-output/error.log перезаписываются при запуске. Ошибки провайдера во время разговора отображает OpenCode; launcher не анализирует тексты чатов для диагностики модели.

После ошибки доступна «Повторить запуск». Эта кнопка запускает runtime, а не повторяет неудачную запись в Encounter/Google. PID блокировки сопоставляется со временем рождения процесса и установкой. Неизвестный/старый формат блокировки сохраняется для ручной проверки; удаляйте его только после подтверждения отсутствия процессов данной установки.

Отдельной кнопки подключения Google нет. При просьбе изменить Docs/Sheets агент использует навык google-documents и браузер. До ввода текста или изменения ячеек он показывает точные правки и ждёт одобрения пользователя. При недостаточных правах предложит войти в Google в браузере или запросить доступ у владельца.
